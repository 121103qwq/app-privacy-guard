# Anthropic 邮件与链接的隐私处理

Anthropic 的验证、登录和通知邮件可能包含远程图片或带参数的链接。邮件隐私与应用出口保护是两层问题。固定美国代理不会自动清理邮件追踪器，邮箱的图片加载方式也不会约束浏览器打开链接后的出口。

## 推荐收件方式

推荐使用 Proton Mail 地址接收 Anthropic 邮件，并在 Proton Mail Web 或官方应用中直接阅读。保持“邮件追踪保护”开启。Proton 官方说明指出，该功能会移除已知追踪像素，通过通用代理加载远程图片，并在 Web 端清理已知的链接追踪参数。

如需在 Gmail 中集中收件，可以使用邮箱提供的转发或导入功能。此方式主要解决收件便利问题。Google 官方说明指出，Gmail 的图片代理会阻止发件方通过图片获得设备和位置，但发件方有时仍能知道邮件是否已经打开。因此，转发到 Gmail 不能表述为“完全避免邮件追踪”。

建议按以下顺序处理 Anthropic 邮件：

1. 使用 Proton Mail 地址接收邮件。
2. 优先在 Proton Mail 中阅读，并核对追踪保护标记。
3. 如需转发到 Gmail，将 Gmail 视为收件汇总层，不把它视为追踪清理层。
4. 不在普通浏览器中直接点击登录或验证链接。
5. 将链接交给已经验证出口的专用 Edge，并保持 Claude、Google 和回调页面位于同一资料中。

不要在仓库、截图或问题报告中发布完整邮件链接。验证链接通常含有一次性令牌。排障时只保留域名、跳转顺序和已脱敏的参数名。

## 邮件追踪的实际边界

邮件追踪保护只能减少已知追踪方式。它不能保证发件方无法判断账号活动。

- Proton Mail 会拦截已知追踪像素，但自定义追踪参数可能无法识别。
- 清理链接参数有时会导致链接失效。失效时应从原邮件重新开始，不要反复传播完整链接。
- Gmail 图片代理可以隐藏设备和位置，但不保证隐藏打开事件。
- 点击链接后，网站仍能看到浏览器出口、Cookie、账号状态和浏览器特征。
- 回复邮件、登录账号和提交表单会主动向服务方产生新的记录。

## 本项目实测得到的经验

本项目没有使用真实 Claude 账号，也没有打开真实 Anthropic 验证邮件。以下经验来自无账号回调、空白浏览器资料、固定代理和故障测试：

- 登录页、Google 登录页、返回 Claude 的页面和应用回调应使用同一受保护环境。中途切到普通浏览器会脱离原保护范围。
- 固定代理端口只配置美国节点。不要添加 DIRECT 回退。上游不可用时，应让受保护应用停止连接。
- WFP 规则负责阻止已覆盖程序直接出网。仅设置系统代理或浏览器代理不能提供同等的断线保护。
- 应先完成美国出口、语言、时区和扩展状态检查，再打开登录链接。一次 IP 检查不能证明后续所有域名使用同一出口。
- 客户端更新可能改变程序路径。更新后应重新发现程序并安装保护规则，然后再开始登录。
- 回调测试应使用 mock state 和 mock code。测试日志不记录 Cookie、令牌、完整回调 URL、邮箱地址或代理凭据。
- 邮箱保护、浏览器保护和应用保护需要分别核对。任意一层通过都不能替代其他层的验证。

已验证内容不包含真实 Anthropic 邮件追踪行为、真实 Google 登录兼容性或真实 Claude 账号风控结果。
